## Concrete implementation decisions

- Report contract identifiers remain `ect-report/0.1`, `ect-core/0.1`, `ect-method/0.1` and `ect-json/0.1`. A valid envelope carries all required dossier/tool/interpreter identity. Invalid envelopes add `diagnostics`, a list of sanitized `{code,pointer}` objects, and omit unadmitted dossier metadata with an explicit limitation.
- Development `build_id` is `unknown`, as permitted by the executable specification. No exact source-build provenance is asserted. The report still captures the actual interpreter version and exact input/result bytes.
- Missing ordinary scope snapshot lists default to empty. A selected snapshot must appear in its scope's list. Wrong-scope review declarations remain admitted but unqualified.
- Evidence `origin_ids` and `transformation_ids` resolve to records without an invented narrower target type; the normative field table gives none.
- Deferred and unselected results have empty `values` and explicit nonexecution reasons. Resource delivery overflow emits a compact partial envelope with affected requests and generated counts. No completed supporting conclusion survives discarded detail.
- Lint explicitly carries `values.open_evaluation`: `not_applicable` for narrow claims and `not_assessed` for open claims. This preserves the specification's finite/open boundary beside the actual conclusion.
- CLI input exceeding 10 MiB is rejected after a bounded read. It emits `INPUT_BYTE_LIMIT` and exit 2 without a fabricated hash of truncated bytes. Byte APIs, which receive the full supplied bytes, can identify those bytes in an invalid-input report.
- Markdown validates current report shapes and digest before rendering. It retains full substantive detail in a fenced JSON block after a compact summary. Evidence bodies and locators never enter the generated report.
- Reports may contain supplied record identifiers. Their use remains local and private by default. Filesystem checks do not claim defense against hostile concurrent directory replacement.

## Verification

Tests use literal expected conclusions and independently stated counterexamples. Cases cover missing/withheld/disputed facts, metadata-only receipts, exact scope, finite expiry, opposing reviews, resolution cycles, counterexample qualification, closed input grammar, malformed links, deterministic selection and byte identity, output safety, report grammar and raw-body nonleakage.

Reproducibility goldens, where present, check normalized cross-runtime output identity only; behavioral expectations remain independent tests. Schema tests detect generation drift. A separate development-only JSON Schema meta-validation checked Draft 2020-12 and all four demos without adding a runtime dependency.

Local verification uses CPython 3.12.14 on Linux. The package check builds an sdist, builds a wheel from the extracted sdist, installs it offline into a fresh virtual environment outside the checkout, and checks CLI/API behavior and all packaged resources. The final pull request records the final test count and CI results.

The four target CI cells are CPython 3.12 and 3.13 on Ubuntu 22.04 and Windows Server 2022. A configured matrix is not itself evidence that a cell passed; use the linked commit's workflow results. Release acceptance and immutable build provenance remain P1-6 work.
