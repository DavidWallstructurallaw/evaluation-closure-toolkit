# Evaluation Closure Toolkit 0.1.0

The first stable software release provides offline AI evaluation dossier auditing through a Python CLI and byte-oriented library. It examines supplied records under explicit scope and the `ect-core/0.1` policy, with inspectable JSON and Markdown reports.

## Included

- Admission checks for bounded local JSON, typed references, timestamps, immutable identities and cross-record bindings.
- Seven operations: claim/disclosure `lint`, structural `profile`, scoped `compare`, evidence `lineage`, `external` contribution accounting, correction `cases` and five-condition `assess`.
- `validate`, `analyze` and `demo` commands, plus `validate_bytes`, `analyze_bytes` and `render_markdown` public functions.
- Fourteen packaged synthetic demos, a dossier schema, readable reports, deterministic rerun guidance and an installed-user guide.
- Zero third-party runtime dependencies, an Apache-2.0 engineering license and explicit resource/delivery limits.
- Exact-source package build IDs and artifact SHA-256 manifests. The wheel is built from the published source distribution.

The six implementation PRs were accepted and merged in dependency order: [#1](https://github.com/DavidWallstructurallaw/evaluation-closure-toolkit/pull/1), [#2](https://github.com/DavidWallstructurallaw/evaluation-closure-toolkit/pull/2), [#3](https://github.com/DavidWallstructurallaw/evaluation-closure-toolkit/pull/3), [#4](https://github.com/DavidWallstructurallaw/evaluation-closure-toolkit/pull/4), [#5](https://github.com/DavidWallstructurallaw/evaluation-closure-toolkit/pull/5) and [#6](https://github.com/DavidWallstructurallaw/evaluation-closure-toolkit/pull/6). The stable preparation updates version metadata and documentation discoverability without changing analytical semantics, schema, policy or budgets.

## Qualification and downloads

Publication requires the final merged source commit to pass all four x64 targets: CPython 3.12 and 3.13 on Ubuntu 22.04 and Windows Server 2022. Each target builds an exact-source sdist and wheel, tests the installed wheel from the extracted sdist, verifies the schema, and checks a fresh offline installation plus the actual README, user-guide and rerun examples. Windows skips two POSIX-only filesystem tests. The published release notes add the exact source revision, build ID and successful workflow URL.

Download the wheel, source distribution and `artifacts.json` from the [0.1.0 release](https://github.com/DavidWallstructurallaw/evaluation-closure-toolkit/releases/tag/v0.1.0). Published distribution assets are the qualified Ubuntu 22.04 / CPython 3.12 build from that same workflow run. Other matrix builds retain their separate artifact hashes; identical package bytes across platforms are not promised.

Check the manifest and independently expected source revision as described in the [release procedure](https://github.com/DavidWallstructurallaw/evaluation-closure-toolkit/blob/v0.1.0/docs/RELEASE.md). Install the downloaded wheel with:

```sh
python -m pip install --no-index --no-deps evaluation_closure_toolkit-0.1.0-py3-none-any.whl
evaluation-closure --version
evaluation-closure demo bounded-workflow --format markdown
```

GitHub's automatically generated source archives are un-stamped checkouts. Use the attached sdist or wheel for the qualified build identity. No PyPI upload is part of this release.

## Limits

Qualification establishes the tested software contracts and synthetic workflows. It does not establish empirical effectiveness, authenticate evidence, certify a model or authorize deployment. Findings remain conditional on the supplied dossier, declared scope and policy. Missing, unknown, unselected and partial evidence remains explicit; no aggregate openness score is produced.

The runtime does not execute benchmarks or models, collect live evidence, fetch locators, capture archives, provide replay/simulation, or depend on a predecessor toolkit. Source papers and private dossiers are not distributed with the software. Reports omit raw evidence bodies and locators, but supplied identifiers can still be private. Build IDs and hashes are metadata, without a signed-attestation claim.

See the [user guide](https://github.com/DavidWallstructurallaw/evaluation-closure-toolkit/blob/v0.1.0/docs/USER_GUIDE.md), [README](https://github.com/DavidWallstructurallaw/evaluation-closure-toolkit/blob/v0.1.0/README.md) and [deterministic rerun guide](https://github.com/DavidWallstructurallaw/evaluation-closure-toolkit/blob/v0.1.0/docs/REPRODUCIBILITY.md) before interpreting results.
