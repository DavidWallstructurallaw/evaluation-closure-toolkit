## Step-specific interpretations

### Typed graph semantics

Adjacency ordering uses relation IDs, and paths list those IDs in traversal order. Parent pointers bound traversal storage; full paths are materialized only for delivered overlap/frontier/terminal/cycle witnesses. A path with no edges means the seed itself. A parentless captured node remains a terminal even if an explicit unknown frontier is also attached. Graph inventory remains conditional on declared relations, including missing attribution or contrary premises, which remain visible.

An independence record is selected by default only for the exact scope and exact seed set; explicit `independence_ids=[]` selects none. An assessment in another dimension stays visible with `applies_to_view=false`. Pairwise reviews are never composed into another pair or a joint set. Missing record method or scope window, a conflicting explicit scope dimension, unresolved contrary reviews, a declared unexamined assessed dimension, or overlap in the same selected dimension blocks affirmative independence support. A qualified favorable review remains visible beside a conflicting shared path, with the conflicting path's relation IDs attached to that criterion's dependencies and contrary basis.

Recursive chronology treats a process entity's `occurred_at` as the occurrence/start of the named process event. Required times satisfy `earlier_process < later_process <= use_event`. Known output or production times additionally must fall between the earlier process and use. Missing process/use times or contradictory known chronology retain the actual path with an unresolved state; version labels do not replace time. An acyclic path can qualify recorded reuse. A static cycle cannot supply chronology. These are documentary process witnesses, with no causal effect estimate.

### External-contact semantics

Event records remain bound to the exact cohort/member and scope. A qualifying yes/no event requires known attribution, event time inside the half-open scope window, the exact checkpoint, and supplied scoped process/observation/intervention receipts with known producers and content. All named supporting evidence must meet those access/type/scope requirements; at least one receipt must identify the member or event in `subject_ids`. Uploading a dossier supplies none of these process events.

Used and selected events require the exact known cohort purpose. Used events additionally identify their target. Retained events additionally identify a representation and a documentary-qualified retention review for the exact member. Explicit nonretention uses the same witness requirements. Contradictory yes/no declarations for the same checkpoint/window/use stay disputed; no latest-record choice or event-level adjudication is implemented. Out-of-window or explicitly different-checkpoint/use records stay visible without contradicting the selected context. Repeated events do not multiply members, and stages are not inferred from one another.

Externality requires a known cohort boundary; use qualification requires the known purpose. Both require a known scope window and separate explicitly selected member reviews. Every matching opposing review is examined. An unqualified selected review cannot be bypassed by an unrelated favorable declaration; an exact qualified resolution can replace it while retaining its history. Review support must include the exact member in evidence `subject_ids`. Member-specific counterevidence remains local even when it also names its parent cohort. Unbound cohort-wide contrary evidence remains a shared unresolved premise.

`documented_current_contact` is a member-level derived summary requiring qualified current-window receipt and use plus separately supported externality and suitability. Carryover cannot receive that summary. A carryover member's independently documented current use remains visible. This summary supplies no continuing-contact adequacy judgment or five-condition support. A known-subset positive witness can survive unknown full cohort membership, while the full member count remains unavailable.

## Report and resource details

Lineage adds selected relation inventory, a cycle state and at most one finite cycle witness beside the required payload fields. Relation roles and independence/reviewer methods are retained through record IDs and fact states rather than copied sensitive text. Every output witness lists its actual relation IDs; declarations and direct contrary references remain dependencies.

External reports add count scope, full member count, fact-state metadata, member completion flags, exact event decisions, retention review details and the bounded contact summary. `membership_state` distinguishes an explicit known `unknown` roster status from an unknown fact. All numeric quantities use the existing numeric state wrapper. A completed partial-membership report counts only its captured roster. An interrupted scan never publishes whole-roster stage totals, though completed member/event witnesses remain visible.

The shared deterministic work budget remains one million units per request and two million per run. At most 100,000 delivered path-edge references can be retained per run. Limits reserve work/path references before publishing the next witness. Review indexes now include exact member/request bindings to avoid repeatedly scanning unrelated member reviews; indexes retain every relevant declaration, including wrong-scope and contrary records. Report/finding limits retain the existing fail-closed delivery behavior.

JSON and Markdown render the same report object. Readable path, dimension and member-stage tables precede the complete inert JSON. The renderer validates connected paths, finite cycle closure, exact counting partitions and contact prerequisites, without re-reading the dossier or treating a digest as authentication. No method prose, evidence body, locator, checkpoint/purpose text or representation body is exported.
